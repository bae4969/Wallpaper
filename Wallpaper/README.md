# Wallpaper

Windows 바탕화면에 움직이는 배경과 큰 플립 시계·월간 달력·하드웨어 상태 위젯을 표시하는 프로그램입니다. 트레이에는 **Wallpaper**로 표시됩니다.

- 큰 `HH:mm:ss` 플립 시계: 기본 위치는 각 디스플레이 정중앙, 위치·크기 변경 가능
- 박스 없는 월간 달력과 오늘 날짜 강조: 기본 위치는 좌하단, 위치·크기 변경 가능
- 하드웨어 상태 위젯: CPU·RAM·GPU별 사용률·VRAM 및 다운로드·업로드 속도, 70% 이상 노랑·90% 이상 빨강 강조
- 하드웨어 위젯을 계속 추가하고 PC별 연결·표시 항목·배치를 개별 저장
- 스크립트 위젯: `widgets\<id>\widget.json` + `widget.xaml`(WPF XAML)로 위젯을 만들고, 설정 창 **위젯** 탭의 **위젯 추가 ▾**로 놓는다. 기본 예제: 디지털 시계·시스템 상태·메모
- 위젯별 설정: 시계(24/12시간·초 표시·넘김 애니메이션·숫자 색), 달력(주 시작 요일·지난·다음 달 날짜·글자 색·오늘 강조 색), 스크립트 위젯(widget.json 의 params), 모든 위젯 공통 배경 진하기·그라데이션 범위
- NAS를 경유해 대상 PC의 SSH 별칭으로 접속하는 2단계 SSH 지원
- 사각형 비율에 맞춘 은은한 검정 그라데이션이 네 가장자리에서 넓고 부드럽게 사라짐
- 다중 모니터: 배경은 메인·서브 2세트 — 메인 모니터(기본: Windows 주 모니터)에는 장면의 메인 구성, 메인 좌우(높이가 겹치는) 모니터에는 메인 풍경을 옆으로 이어 그리고, 그 밖(아래 등)의 모니터에는 서브 구성을 그린다. 서브는 실제 모니터 위치에 맞춰 메인 아래로 이어지거나(continue) 메인을 수면처럼 비춘다(mirror). 별·눈·꽃잎 같은 입자는 모든 모니터를 합친 가로 범위에 퍼진다. 메인은 21:9·16:9 모두 지원. 위젯 구성·배치는 디스플레이마다 따로 저장
- 트레이 아이콘(왼쪽·오른쪽 클릭) → **설정**: 탭 4개 — **디스플레이**(배경 세트·메인 모니터·서브 모니터·레이아웃 편집), **위젯**(메인/서브 전환·추가·제거·설정), **장면**(목록·새로 만들기·복제·이름·편집·삭제), **성능**(프레임 제한·렌더 해상도·효과 품질·멈춤 조건)
- 움직이는 배경: 레이어를 쌓아 만든 장면(예: 비 오는 네온 도시, 블랙홀, 우주 성운, 새벽 유성우, 노을 바다, 벚꽃 노을, 눈보라 설산, 아침 숲, 여름 들판, 컬러 유체, 매트릭스, 지형도, 검은 파도, 오로라 호수, 네온 강변 도시, 하늘 거울 — 모두 메인·서브 2세트). 장면과 레이어 종류는 모두 스크립트 파일(JSON + HLSL)이라 코드 수정 없이 추가·수정
- 레이아웃 편집에서 시계·달력을 개별 이동하고 모서리로 크기 조절, 변경 즉시 바탕화면에 반영
- 화면 중앙·가장자리와 다른 위젯의 정렬선에 가까워지면 자동 스냅 및 가이드 표시
- 위젯 위의 마우스 클릭은 바탕화면으로 통과
- 파일 아이콘이 위젯보다 앞에 표시됨
- 트레이 메뉴의 **종료**를 누르면 닫힘
- 같은 실행파일을 다시 열어도 중복 실행되지 않음

## 실행

작업 폴더의 `build/Wallpaper.exe`를 더블클릭합니다(예전 이름 DesktopClock). 예전 데이터 폴더 `%LOCALAPPDATA%/DesktopClock`이 있으면 처음 실행할 때 `%LOCALAPPDATA%/Wallpaper`로 옮겨 설정·장면·위젯을 그대로 씁니다. 트레이 아이콘은 실행파일 경로별로 등록되므로 exe를 옮기면 아이콘 표시 설정(숨김 여부)만 처음 상태가 됩니다. .NET 10 런타임을 포함한 x64 전용 압축 단일 실행파일이라 .NET 설치는 필요 없습니다. 실행파일 하나만 복사해서 사용할 수 있습니다. 실행 시 WPF 네이티브 라이브러리는 `%TEMP%/.net/Wallpaper/`에 풀립니다.

처음 실행하면 주 디스플레이에 시계·달력을 켜고 트레이 알림으로 사용법을 알립니다. 트레이 아이콘을 왼쪽 또는 오른쪽 클릭하면 `Wallpaper` / **일시정지**(누르면 **재개**로 바뀜) / **설정** / **종료** 메뉴가 열립니다. 일시정지하면 모든 화면의 움직이는 배경이 마지막 프레임에서 멈추고(GPU 사용 0) 툴팁이 "Wallpaper (일시정지됨)"이 됩니다. 시계·달력 등 위젯은 계속 동작하며, 일시정지는 다음 실행에 이어지지 않습니다. 설정 창에서 디스플레이를 고르고 **레이아웃 편집**을 누르면 그 화면의 편집 창이 열립니다. 디스플레이마다 시계·달력·하드웨어 위젯의 표시 여부와 위치·크기를 따로 가집니다. 배경은 세트 하나를 모든 화면에 함께 적용합니다. 처음 연결된 디스플레이는 위젯 없이 시작하며 설정 창 **위젯** 탭에서 추가하고, 레이아웃 편집의 **위젯 ▾**에서 켜고 끕니다. 설정은 `%LOCALAPPDATA%/Wallpaper/preferences.xml`에 저장되며 다음 실행에도 유지됩니다. 연결이 끊긴 디스플레이의 설정은 보관하고, 다시 연결되면 저장된 배치로 표시합니다. 디스플레이는 Windows 장치 이름(`\\.\DISPLAY1` 등)으로 구분합니다. 예전 버전에서 "사용 안 함"으로 둔 디스플레이는 위젯을 모두 끈 상태로 옮겨 읽습니다.

편집 창에서는 위치·크기를 조절하고 툴바의 **위젯 ▾** 체크 메뉴로 위젯을 켜고 끕니다(바로 반영·저장, 메뉴는 여러 개를 연달아 바꿀 수 있게 열린 채 유지). 배경과 위젯 추가·제거·설정은 설정 창에서 합니다. 하드웨어 위젯은 꺼져 있는 동안 수집을 멈춥니다. 편집하는 동안 설정 창은 숨고, 편집을 마치면 다시 나타납니다. 편집 화면의 배경은 그 디스플레이의 실제 배경을 보여 줍니다 — 움직이는 배경이면 편집을 연 시점의 장면 한 프레임, 아니면 Windows 배경화면입니다. 위젯 내부를 드래그해 이동하고 네 모서리의 핸들로 비율을 유지하며 크기를 조절합니다. 움직이는 동안 실제 바탕화면에도 바로 반영됩니다. 이동과 크기 조절 모두 중앙·가장자리·다른 위젯의 정렬선 근처에서 자동으로 맞춰지고 보라색 가이드가 나타납니다. 크기 조절은 반대쪽 모서리를 고정한 채 움직이는 가장자리나 중앙선을 맞춥니다. **완료** 또는 `Esc`로 편집을 마치면 위치와 크기가 저장됩니다.

설정 창 **디스플레이** 탭의 **배경 세트**에서 Windows 배경화면 또는 장면을 고르면 메인·서브에 함께 바로 적용·저장됩니다. **메인 모니터**에서 메인으로 쓸 화면을 고르고(나머지는 서브), 메인·서브 카드마다 **레이아웃 편집**이 있습니다. 예전 버전에서 화면마다 고른 배경은 처음 고른 장면을 세트로 옮겨 읽습니다. **위젯** 탭은 **메인 모니터**·**서브 모니터** 버튼으로 화면을 고르며(서브가 여럿이면 목록에서 고름), 목록의 **설정**으로 위젯별 옵션을 바꿉니다(바로 반영, 설명은 ⓘ). 꺼진 위젯은 목록에 "꺼짐"으로 표시됩니다. **위젯 추가 ▾** 메뉴에는 **하드웨어 상태 (내 PC · SSH)**와 widgets 폴더의 스크립트 위젯이 함께 나옵니다. 시계·달력은 **설정**만, 나머지는 **설정**·**제거**가 있습니다. 모든 위젯의 설정에 배경 진하기·그라데이션 범위가 있으며, 위젯 뒤 그라데이션은 내용 가장자리에서 바깥으로 지정한 범위만큼 부드럽게 사라집니다. 새 위젯은 켜진 상태로 놓이고, 다시 켜면 마지막 위치와 크기를 사용합니다. 하드웨어 상태는 저장할 때마다 새 위젯이 목록 끝에 추가되며, 같은 이름이나 같은 PC도 별도 위젯으로 추가할 수 있습니다. 하드웨어 상태의 **설정**에서 이름·연결 대상·갱신 간격·표시 항목·모양을 바꿉니다. **제거**는 해당 위젯을 삭제합니다.

하드웨어 상태는 C# 내장 위젯입니다. 스크립트 위젯은 보안상 XAML 화면과 이 PC의 측정값만 쓸 수 있어 SSH로 다른 PC를 읽을 수 없기 때문입니다. 이 PC만 볼 때는 스크립트 위젯 "시스템 상태"로도 충분합니다.

이동·크기 조절 박스는 숫자와 달력 등 실제 내용 영역을 감쌉니다. 그라데이션 여백은 박스 바깥에 유지되고, 내용을 화면 가장자리에 붙이면 바깥 여백은 해당 모니터 경계에서 잘립니다. 페이드 합성은 같은 모니터의 위젯끼리만 합니다. 기존에 저장한 배치도 그대로 읽습니다.

위젯의 페이드가 겹치면 가장 큰 투명도 값을 공유하고, 모든 위젯의 내용은 그 위에 합성합니다. 여백이 다른 위젯의 글자를 지우거나 겹친 부분이 이중으로 어두워지지 않습니다. 그라데이션에는 미세한 디더링을 적용해 넓은 페이드의 색상 경계를 줄였습니다. 편집 미리보기에도 같은 합성 기준을 적용합니다. 새 하드웨어 위젯은 기존 내용 영역과 겹치지 않는 공간부터 배치합니다.

하드웨어 상태는 기본 2초마다 백그라운드에서 갱신하며, 각 위젯에서 1~60초로 변경할 수 있습니다. GPU 사용률·VRAM·온도·전력은 NVIDIA 드라이버의 `nvidia-smi`로 읽습니다. CPU·RAM과 다운로드·업로드 속도도 표시합니다. 사용률이 70% 이상이면 노란색, 90% 이상이면 빨간색으로 막대와 퍼센트를 강조합니다. CPU와 네트워크 속도는 두 번의 측정이 필요하므로 처음에는 `—`로 표시됩니다. GPU 정보가 없는 경우에도 나머지 항목은 사용할 수 있습니다. PC별 수집은 독립적으로 실행하며 한 연결의 실패가 다른 위젯을 멈추지 않습니다.

연결 대상으로 **리눅스 PC · SSH**를 선택하면 주소 또는 기존 SSH 호스트 별칭을 입력할 수 있습니다. 사용자·포트·키 파일은 선택 사항이며 비워두면 기존 SSH 설정을 사용합니다. Windows의 OpenSSH 클라이언트와 키 또는 SSH 에이전트 인증을 사용합니다. 암호화된 키는 에이전트에 등록해야 합니다. 원격 PC에는 `python3`가 필요하고 GPU 항목은 NVIDIA 드라이버와 `nvidia-smi`가 필요합니다. btop 설치는 필요 없습니다. CPU·RAM·네트워크는 Linux `/proc`에서 읽으며 네트워크는 기본 IPv4 경로의 인터페이스를 사용하고, 기본 경로가 없으면 루프백을 제외한 첫 인터페이스를 사용합니다.

설정의 **연결 확인**으로 응답을 확인할 수 있습니다. 처음 연결하는 PC의 호스트 키는 터미널에서 해당 PC에 SSH 접속해 확인해야 합니다. SSH 연결을 유지하며 실행파일에 포함된 수집 코드를 전달하고, 원격 PC에 파일이나 서비스를 설치하지 않습니다. 연결이 끊기면 위젯에 상태를 표시하고 자동으로 재연결합니다. 기존 단일 하드웨어 설정은 위치·크기를 유지하며 새 목록으로 읽습니다.

`ssh nas` 후 NAS에서 `ssh node1`로 접속하는 경우, **경유 SSH 호스트**에 `nas`, **SSH 주소 또는 호스트 이름**에 `node1`을 입력합니다. 대상 PC의 사용자·포트·인증은 NAS의 SSH 설정을 사용하며, 사용자와 포트를 직접 지정할 수도 있습니다. 경유 호스트는 `사용자@주소:포트` 형식도 지원합니다. 경유 설정에서 선택한 접속 키 파일은 Windows에서 NAS에 접속할 때 사용합니다. 대상 PC에 대한 키와 호스트 키 확인은 NAS에 있는 SSH 설정을 사용합니다. GPU가 없는 PC는 GPU·VRAM 행을 표시하지 않습니다.

## 움직이는 배경

설정 창 **디스플레이** 탭의 **배경 세트**에서 장면을 고릅니다. 장면은 메인·서브 2세트입니다. 앱이 실제 모니터 배치(크기·위치)를 셰이더에 넘기므로 서브는 손으로 맞추지 않아도 메인과 경계에서 이어지고, 모든 화면이 같은 시계를 써서 반사·이어짐이 같은 순간을 그립니다. 장면은 아이콘 바로 뒤에 GPU(Direct3D 11)로 그리며, 시계·달력·하드웨어 위젯은 장면 위에 같은 그림자 규칙으로 합성합니다. 클릭은 그대로 바탕화면으로 통과합니다. 최대화·전체 화면 창이 디스플레이를 덮으면 그 디스플레이의 애니메이션을 멈추고, 창이 사라지면 다시 그립니다. 레이아웃 편집 화면에는 편집을 연 시점의 장면 한 프레임을 배경으로 보여 줍니다.

Windows 11 24H2 이후의 바탕화면 구조(Progman 아래 아이콘·배경 층)에서 동작합니다. 장면은 `Progman`의 자식인 불투명 레이어 창을 아이콘 층 바로 뒤, Explorer 배경 층 앞에 두고 그 안의 자식 창에 flip 모델 스왑체인으로 그립니다. Explorer가 순서를 바꾸면 2초마다 되돌리고, Explorer가 다시 시작되면 새로 만듭니다.

### 설정 창

트레이 → **설정**을 누르면 열리며 **디스플레이 / 위젯 / 장면 / 성능** 탭으로 나뉩니다. 창과 대화 상자는 모두 같은 다크 테마(얇은 스크롤바 포함)입니다. **디스플레이** 탭은 배경 세트, 메인 모니터(고르기·해상도·켜진 위젯 수), 서브 모니터 목록(서브 구성 방식)으로 나뉘고, 각 화면의 **레이아웃 편집**을 누르면 그 화면의 편집 창이 열립니다. 편집 창을 닫거나 화면 구성이 바뀌면 고른 화면을 유지한 채 정보를 새로 고칩니다. 장면에 오류가 있으면 배경 옆에 표시합니다.

**장면** 탭은 장면 파일 목록을 메인·서브 미리보기 그림(지금 모니터 비율·배치로 뒤에서 하나씩 그림)·이름·서브 방식·레이어 수와 함께 보여 줍니다. 읽지 못한 장면은 오류를 빨갛게 표시합니다. **새 장면**은 그라데이션·가장자리 어둡게 메인과 수면 반사 서브로 된 2세트 틀을 만들고 파일을 엽니다. 실행파일에서 빠진 예전 기본 장면(2세트로 합친 서브 전용 장면)은 고치지 않았으면 자동으로 지웁니다. 장면마다 **이름**(파일의 `name`만 바꾸고 주석은 유지), **복제**(이름 뒤에 "복사본"), **편집**(JSON을 기본 편집기로, 없으면 메모장), **삭제**가 있습니다. 사용 중인 장면을 지우면 확인 후 그 화면을 Windows 배경화면으로 돌립니다. 지운 기본 장면은 `.defaults`에 기록해 다음 실행에 다시 풀리지 않습니다. 파일을 저장하면 실행 중인 화면과 목록에 바로 반영됩니다. **폴더 열기**는 장면·레이어·위젯 스크립트 폴더를 엽니다.

**성능** 탭의 옵션은(각 옵션의 설명은 제목 옆 ⓘ에 마우스를 올리면 보입니다), 바꾸면 바로 적용·저장됩니다(`preferences.xml`의 `performance`).

| 옵션 | 값 | 동작 |
|------|-----|------|
| 프레임 제한 | 15 / 20 / 24 / 30 / 40 / 45 / 50 / 60(기본) / 72 / 90 / 100 / 120 / 144 FPS / 디스플레이 주사율 | 주사율보다 낮으면 고해상도 대기 타이머로 간격을 맞추고, 같거나 높으면 수직동기에 맡긴다. 그리는 중에 바뀐다 |
| 렌더 해상도 | 100(기본) / 90 / 80 / 75 / 70 / 60 / 50 / 40 / 33 / 25% | 배경 레이어를 낮은 해상도로 그린 뒤 확대한다. 위젯은 항상 원래 해상도. 바꾸면 장면을 다시 만든다 |
| 효과 품질 | 최고(기본) / 높음 / 보통 / 낮음 / 최저 | 입자 수 100·80·60·45·30%, `Fbm` 반복 5·4·4·3·3회, 최저에서는 `post` 레이어(유리 등)를 건너뛴다. 셰이더에 `Quality`(2·1.5·1·0.5·0)로 전달된다. 예전 높음·보통·낮음 설정은 최고·보통·최저로 읽는다 |
| 창이 화면을 덮으면 멈춤 | 켬(기본) | 최대화·전체 화면 창 뒤에서는 그리지 않는다 |
| 배터리로 작동할 때 멈춤 | 켬(기본) | 전원에 연결되지 않으면 그리지 않는다 |

1920×1200·약 100Hz 화면에서 "비 오는 네온 도시"의 측정값(GPU 3D 엔진 사용률): 30 FPS 0.8%, 60 FPS 1.7%, 주사율(약 100fps) 2.8%, 60 FPS·50% 0.9%, 60 FPS·효과 낮음 1.0%. 메인 3440×1440 + 서브 1920×1200에 2세트를 60 FPS·효과 최고로 그리면 장면에 따라 약 2.6%(검은 파도)~8.4%(여름 들판), 아침 숲은 14.6%.

### 장면 스크립트

장면과 레이어 종류는 코드가 아니라 `%LOCALAPPDATA%/Wallpaper/Wallpapers/`의 파일입니다. 기본 파일은 실행파일에 들어 있습니다. 폴더에 없는 파일을 채우고, 이미 있는 기본 파일은 사용자가 고치지 않았을 때만(처음 풀 때 `.defaults`에 기록한 해시와 같을 때만) 새 버전으로 바꿉니다. 고친 파일은 덮어쓰지 않습니다.

```
Wallpapers/
  AUTHORING.md               장면 작성 안내서(형식·slot·셰이더 상수·예제)
  errors.log                 장면 오류 기록
  layers/common.hlsli        모든 레이어 셰이더 공통 헤더
  layers/<종류>.hlsl + .json 레이어 종류 = 셰이더 + 값 정의(slot·기본값·설명)
  scenes/<id>.json           레이어를 쌓은 장면
```

기본 레이어 종류는 `gradient`(하늘)·`skyline`(빌딩)·`particles`(보케·빗줄기·빛 점)·`fog`·`flash`(번개)·`glass`(빗방울 유리 후처리)·`vignette`·`aurora`(오로라)·`ridge`(산 능선)·`water`(잔물결 수면 후처리)·`meteor`(별똥별)과 `blackhole`·`nebula`·`sun`·`clouds`·`ocean`·`grass`·`petals`·`forest`·`lightrays`·`fluid`·`matrix`·`contour`·`linewaves`이며, `.hlsl`과 `.json`을 추가하면 새 종류가 생깁니다. 트레이 앱이 실행 중이면 폴더의 파일을 저장할 때마다 그 장면을 쓰는 화면을 바로 다시 그립니다. 장면을 만들 수 없으면 그 화면은 Windows 배경화면으로 표시하고 트레이 알림과 `errors.log`에 원인(레이어 번호, 셰이더 줄 번호, 알 수 없는 값 이름)을 남깁니다.

### 명령줄 도구 (사람·AI용)

실행파일에 인자를 주면 트레이 앱 대신 장면 도구로 동작합니다. AI가 실행파일만 보고도 장면을 만들 수 있도록 안내서를 내장했습니다.

```
Wallpaper.exe --help                    도움말
Wallpaper.exe --guide                   장면 작성 안내서(AUTHORING.md) 출력
Wallpaper.exe --folder                  장면 폴더 경로(기본 파일 채움)
Wallpaper.exe --list                    장면·레이어 종류·값 목록
Wallpaper.exe --validate [장면]          컴파일 검사(실패 시 종료 코드 1)
Wallpaper.exe --render <장면|json> out.png [--time 3] [--size 1920x1080] [--part main|sub] [--main 2560x1440] [--at X,Y]
                                            바탕화면 없이 한 프레임을 PNG로 저장(--part sub: 서브 쪽)
Wallpaper.exe --render-set <장면|json> out.png [--main 3440x1440] [--sub 1920x1200] [--at 796,1440] [--screen WxH@X,Y]... [--scale 0.5]
                                            여러 모니터를 실제 배치대로 한 장에 저장(옆 모니터는 --screen)
```

출력은 UTF-8이며 `--out <파일>`로 파일에 쓸 수 있습니다.

## 빌드

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Wallpaper\build.ps1
```

.NET 10 SDK가 필요합니다. `Wallpaper.csproj` 설정에 따라 `dotnet publish`로 작업 폴더(`Wallpaper` 폴더의 상위)의 `build/Wallpaper.exe` 하나를 만들고, 중간 산출물은 `Directory.Build.props` 설정에 따라 같은 `build/obj/`에 둡니다.

`Program.cs`는 실행·트레이·배치, `Widgets.cs`는 플립 시계와 달력, `DesktopHost.cs`는 바탕화면 표시, `WallpaperBackdrop.cs`는 기존 배경 합성을 담당합니다. `SettingsWindow.cs`가 성능 설정을, `LayoutEditorWindow.cs`가 디스플레이별 편집(위젯·배치·배경)을 제공하고 `UserPreferences.cs`가 배치와 배경을 저장합니다. `WallpaperScene.cs`는 움직이는 배경의 창 구성·렌더 스레드·레이어 실행·위젯 합성·PNG 렌더를, `SceneLibrary.cs`는 장면 폴더(기본 파일 채우기·레이어 정의 해석·변경 감시·오류 기록)를, `WallpaperCommands.cs`는 명령줄 도구를 담당합니다. `Wallpapers/`는 실행파일에 넣는 기본 장면·레이어·안내서이고, `WidgetShaders.hlsl`은 위젯 합성용 내부 셰이더입니다. `Styles/ModernControls.xaml`은 트레이 메뉴와 편집 창 배경 영역의 다크 테마(Win11 Fluent Dark 서피스 + 바이올렛 강조, ai_agent와 같은 토큰)이고 `ModernTheme.cs`가 창·메뉴 단위로 붙입니다. 위젯 화면에는 적용하지 않습니다. 트레이는 H.NotifyIcon.Wpf로 표시하며 효율 모드는 끕니다. `app.ico`는 실행파일·창·트레이에 함께 쓰는 아이콘(라벤더 `#C6B8FF` 바탕, `#202020` 시곗바늘)입니다.

`WidgetCatalog.cs`는 추가 가능한 위젯 목록, `GpuWidget.cs`는 GPU 조회와 하드웨어 표시, `SystemMetrics.cs`는 CPU·RAM·네트워크 측정을 담당합니다.

`HardwareWidgetSettings.cs`는 항목별 설정, `HardwareSettingsWindow.cs`는 위젯 설정 창, `HardwareFeed.cs`는 PC별 수집·SSH 연결·종료, `LinuxMetrics.py`는 실행파일에 포함되는 Linux 수집 코드를 담당합니다.

플립 모션은 실제 경과 시간을 기준으로 60fps 간격에 맞춰 갱신합니다. 정적 시계 배경은 위치·크기·배경화면이 바뀔 때 다시 합성하고, 애니메이션이 끝나면 프레임 타이머를 멈춥니다.

달력은 일요일부터 시작하며 공휴일 정보는 포함하지 않습니다. 날짜와 시간은 PC의 현지 시간을 따릅니다.

## 검증

Windows 빌드 26300, 모니터 3대 구성에서 세 디스플레이의 선택·이동을 실제 설정 UI로 검증했습니다. 실제 마우스 드래그와 모서리 크기 조절 중 바탕화면 반영, 가로·세로 중앙 스냅, 독립적인 달력 이동, 재실행 후 디스플레이·위치·크기 복원을 확인했습니다. 파일 아이콘 아래 표시, 클릭 통과, `Win+D`, 트레이 종료, 플립 애니메이션 및 달력 날짜 전환도 검증했습니다.

하드웨어 위젯은 실제 설정 UI에서 같은 이름으로 추가, 설정 변경, 중간 항목 제거 후 추가, 여러 디스플레이 전환, 재실행 복원 및 긴 목록의 스크롤을 검증했습니다. 로컬 수집과 실패하는 SSH 연결을 동시에 실행해 독립적인 갱신·종료도 확인했습니다. Linux 수집 계산은 검증용 `/proc` 입력과 GPU 출력으로 확인했고, 실제 `nas → node1` 경로에서 CPU·RAM·네트워크와 GPU 2개 수집 및 설정 창의 연결 확인도 통과했습니다. 겹침 합성은 동일 좌표의 색상 일치·공유 페이드 투명도·내용 보존·숨김 후 재합성을 확인했습니다. 변경 후 시계 프레임 간격 중앙값은 약 16ms였고 정지 구간에는 애니메이션 타이머가 멈췄습니다.

배경화면 표시는 Windows 셸의 `WorkerW` 계층을 사용합니다. 다른 Windows 빌드는 해당 PC에서 확인이 필요합니다.
